How URL percent-encoding works

Uniform Resource Identifiers (URIs) must adhere to the ASCII character set. Any characters outside this range, as well as reserved structural characters, must be converted into their respective percent-encoded hex values.

  • Spaces: Replaced by %20 (or + in historical form POST data).
  • Query Delimiters: & becomes %26, = becomes %3D, and ? becomes %3F.
  • Slashes & Protocols: / becomes %2F and : becomes %3A when encoded with encodeURIComponent.

encodeURI vs. encodeURIComponent

Understanding the distinction between these two encoding approaches is critical when working with web APIs:

  • Use encodeURI: When you are encoding an entire web URL (e.g. https://example.com/products/item?ref=web). It keeps http://, slashes, and question marks intact while encoding spaces and Unicode characters.
  • Use encodeURIComponent: When encoding individual query parameter values (e.g. passing a search phrase or redirect URL). It encodes slashes, ampersands, and equal signs to prevent parameter injection.

Frequently asked questions

Why do URLs need to be encoded?

URLs can only travel across HTTP/HTTPS networks using ASCII characters. Encoding ensures international characters, spaces, and reserved symbols do not break web server routing or API parameter structures.

Does this tool work securely offline?

Yes. All conversions and parameter extractions take place entirely inside your web browser. None of your links, search terms, or API tokens are sent over the network.

What does the Query Parameters table show?

When a decoded link contains URL query arguments (such as ?user=123&category=books), the inspector automatically parses them into individual key-value rows for easy inspection.
