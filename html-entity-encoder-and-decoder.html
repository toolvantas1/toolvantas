Why use HTML entities?

In HTML, certain characters are reserved for code syntax. For example, web browsers interpret < and > as opening and closing HTML tags. If you want these characters to display as visible text on a page, they must be converted into their respective entity representations.

  • &lt; displays the less-than symbol (<).
  • &gt; displays the greater-than symbol (>).
  • &amp; displays the ampersand symbol (&).
  • &quot; displays a double quote (").
  • &#39; displays a single quote (').

Named vs. Numeric Entities

Entities can be written in three distinct formats:

  • Named Entities: Easy to read human shorthand (e.g., &copy; for © or &euro; for €). Note that not all symbols have official named entity aliases.
  • Decimal Entities: Uses the Unicode code point in base 10 (e.g., &#169; for ©). Universally supported by all web browsers and XML parsers.
  • Hexadecimal Entities: Uses the hexadecimal Unicode value (e.g., &#xA9; for ©). Frequently used in programming strings and stylesheets.

Frequently asked questions

Does this tool support all HTML5 entities?

Yes. Decoding uses the browser's native HTML parser engine, ensuring support for all 2,000+ official HTML5 named entities, decimal points, and hexadecimal codes.

What does the "Strip HTML Tags" button do?

It safely strips out all surrounding HTML markup tags (e.g., <p>, <div>, <span>), leaving behind only the plain text content.

Will entity encoding protect against XSS (Cross-Site Scripting)?

Encoding special characters such as <, >, and & prevents untrusted user input from being executed as active HTML or JavaScript when rendered into web documents.

What is the difference between named, decimal, and hex entities?

Named entities use friendly alphanumeric aliases (e.g. &amp;), while decimal (&#38;) and hexadecimal (&#x26;) represent the underlying Unicode code point directly.
