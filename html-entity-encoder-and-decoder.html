Why use HTML entities?

In HTML documents, characters like <, >, &, and quotes control tag and attribute parsing. Converting them into character entities lets browsers render literal code snippets and symbols safely.

  • &lt; displays the less-than symbol (<).
  • &gt; displays the greater-than symbol (>).
  • &amp; displays the ampersand symbol (&).
  • &quot; displays a double quote (").
  • &#39; displays an apostrophe / single quote (').

Named, Decimal & Hex Unicode Code Points

Unlike older tools that split emojis into invalid UTF-16 surrogate pairs, this encoder iterates full Unicode code points:

  • Named Entities: Readable aliases such as &copy; (©), &euro; (€), and &mdash; (—).
  • Decimal Entities: Base-10 code points such as &#169; (©) or &#128640; (🚀).
  • Hexadecimal Entities: Base-16 code points such as &#xA9; (©) or &#x1F680; (🚀).

Frequently asked questions

Does this tool support all HTML5 entities and emojis?

Yes. Encoding uses full Unicode code points (so emojis like 🚀 become valid &#128640; or &#x1F680;), and decoding supports over 2,000 official HTML5 named, decimal, and hex entities.

What does the "Strip HTML Tags" button do?

It removes surrounding HTML markup tags (such as <p>, <div>, and <span>), leaving behind plain text content.

Does entity encoding help prevent Cross-Site Scripting (XSS)?

Encoding reserved characters such as <, >, &, ", and ' prevents untrusted user text inside HTML elements and quoted attributes from executing as active markup.

What is the difference between named, decimal, and hex HTML entities?

Named entities use friendly aliases (&amp;), while decimal (&#38;) and hexadecimal (&#x26;) represent the Unicode code point numerically.

Is my HTML snippet sent to an external server?

No. All encoding, decoding, and tag stripping execute locally inside your browser.
